# Covered movement investigation: issue #128

The original historical investigation recorded a failure of the unchanged high-tier desktop movement floor on the engine tested then. A native run without CPU-profiler sampling measured covered movement at 30.0 FPS, p95 50 ms, low quality. It exercised real alternating steering, travelled 3.36 m, retained outlines on every sampled covered frame, donated and kept all 26 required particles. Its worst overlay took 29.4 ms. Ordinary movement also failed in that run; native scheduling and quality adaptation vary, so a single FPS comparison is not an optimization claim.

[Evidence](covered-movement-128-evidence.json) records the exact existing suite conditions and result. `npm run build` followed by `node scripts/profile-covered-movement.mjs` reuses the suite's actual wallPerformance workload and acceptance checks. `--cpu` additionally writes a DevTools CPU profile under ignored `untracked/`; sampling adds overhead. Failures return a nonzero status. No automatic test scripts or acceptance thresholds change.

The committed evidence above is the original investigation capture, before the October 6, 2026 `rock` integration; it has no recorded source revision or capture date and must not be treated as a current-head measurement. New helper captures include the UTC capture time, browser version and SHA-256 hashes of the built page and suite. The helper requires both workload results and closes its browser even if setup, evaluation or evidence writing fails. Check power state and run without other browser workloads before drawing timing conclusions.

[Historical integration capture: October 6, 2026 at 07:40 UTC](covered-movement-128-current-evidence.json), from `cd668b744faf206bed08c21fd034bb3d5ae0eb5a` on AC power with other task browser runs paused, recorded a failure of the floor at that revision, before merged #173 and the current branch head. Ordinary movement reached 55.82 FPS at high quality but failed p95 (33.3 ms). Covered movement reached 29.11 FPS at low quality, p95 50 ms, worst frame gap 197.9 ms and worst-frame overlay 31 ms; it travelled 4.01 m, retained outlines on all 147 sampled frames and donated with 26 particles. Browser logs were empty. The helper returned status 1 as required. These are diagnostic results, not a passing performance acceptance; no renderer or contour algorithm was changed in this PR.

Historical CPU profiles identify owner-union boundary searches as the main contour cost, with terrain sight queries and overlay compositing also significant. Increasing per-triangle grid capacity reduced BVH fallbacks substantially but did not restore the floor. Finer owner grids, broad-triangle side lists, analytical interval unions and whole-cell triangle certificates either failed to improve the workload or regressed it. Those prototypes were discarded; the profiling investigation changes no shipped engine behavior.

The current branch includes merged [#173](https://github.com/OogaBoogaX/oogaboogaland/pull/173), which fixed some categories in the earlier failure inventory. Its [final approval](https://github.com/OogaBoogaX/oogaboogaland/pull/173#pullrequestreview-5463503020) retained performance and broader browser-acceptance limitations. No fresh controlled performance capture or full-suite run is established by this PR; the historical results establish neither current FPS success nor a current regression. [Issue #128](https://github.com/OogaBoogaX/oogaboogaland/issues/128) remains open.

Historical validation at `47867d40a2126003a85ca751ba2717c737ae15b3` reported build and syntax passes, unit 131/131, site staging 11 pages/9 cards and Worker 36/36; the full browser/protocol/unit suite reported 701/720 in 11.8 min, exit 1. Its failures included movement latency, routes, gorilla, melee, phone layout, cameras, Timechain watchdog and Factory/DSB travel deadlines before resource counters. This is a historical failure inventory, not an inventory for the current head.

A substantive performance change needs to reduce contour work while proving current clipping, tiny openings, motion, world anchors, mode transitions and both renderer behavior. Pose quantization, fewer particles, lowered quality and relaxed thresholds are not supported by these results. This is an investigation and reusable profiling tool, not a fix or a closure claim for #128.
